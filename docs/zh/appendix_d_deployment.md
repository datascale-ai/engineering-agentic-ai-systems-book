# 附录D：部署档位与验收模板

**Deployment Tiers and Acceptance Records**

**摘要**　本附录把部署选择和生命周期验收整理为可填写、可回查的工程记录。先比较单机、队列 worker 与多租户三种档位，明确状态、身份、并发和恢复前提，再沿上线、灰度、回滚与退役说明需要保存的输入、检查、结果和责任。四份完整样例来自本地原创任务与模拟服务的实际运行，分别记录正常上线、配置错配阻断、路由恢复和停止接收新任务。样例只证明对应本地边界，不替代生产发布、真实身份治理或跨机器验证。

**关键词**　部署档位（deployment tier）；验收（acceptance）；灰度（canary rollout）；回滚（rollback）；退役（decommissioning）；责任交接（handoff）。

主责学生 E，正式姓名、单位和适用声明随全书确认。篇幅预算约 7 个等效出版页，实际页数待模板试排。原创示例、代码与夹具沿用仓库 MIT 许可；无真实业务或个人数据。方法前提见 [Ch30](part7/ch30_production_governance.md)、[Ch33](part8/ch33_enterprise_adoption.md)、[Ch36](part9/ch36_reference_implementation.md) 和 [Ch37](part9/ch37_agent_testing.md)；发布流程由 [Ch39](part9/ch39_deployment_continuous_delivery.md) 统一衔接。本附录当前为中文初稿，F 的独立复核另行记录。

## D.1 怎样使用部署档位与验收记录

部署档位应根据任务范围、状态归属、隔离和恢复要求选择。运行在一台机器上不等于只能处理一个角色；使用队列也不自动获得可靠接管；在记录中加入 tenant 字段更不等于已经实现真实租户认证。选型时应先列出必须保护的边界，再看当前实现和证据支持哪一档能力。

每次操作都绑定输入版本和实际证据。最低记录项为操作 ID、目标边界、源代码与数据身份、配置、前置条件、命令、预期、实际、退出码、作用检查、停止条件、责任与剩余事项。版本号说明维护者赋予的名称，内容摘要帮助发现漂移；二者都不能独自证明发布包可信或满足某个供应链等级。Ch36 对锁与运行清单作进一步解释。

本附录使用四种状态：**已运行**表示对应命令与观察可定位；**教学设定**表示参数仅为本次演练选择；**待团队复核**表示需要其他成员确认；**未验证**表示当前没有相应证据。已运行不自动升级成已批准上线，某个保护检查通过也不表示整个系统适合生产。

## D.2 三种部署档位

### D.2.1 单机：先把状态和作用解释清楚

单机适合教学、开发和边界较小的任务。它把环境与故障变量控制在本地，便于先核对任务、运行清单与业务作用。仍需明确进程退出后哪些状态持久化、哪个数据库保存业务结果，以及恢复是否复用原操作标识。本地客户端状态与模拟服务状态分别存储，不存在跨两库事务；中断可以落在两次提交之间。

示例使用原有 `run.py`。从仓库根目录执行下列命令，路径使用尚不存在的新名称：

```powershell
uv sync --project examples/ch36 --python 3.12 --locked
uv run --project examples/ch36 --python 3.12 --locked python examples/ch36/run.py reproduce --output outputs/single-first
```

该入口演示三个最小教学切片，输出独立摘要、事件和模拟服务状态。PRJ-3 切片在服务提交后中断，再启动另一个客户端进程恢复。它检验的是特定中断窗口与稳定操作标识，不是高可用平台，也没有证明主机故障、断电、磁盘损坏或网络分区下仍能提供服务。

### D.2.2 队列 worker：让领取、交接与结果具有持久身份

队列档位增加任务领取、租约、候选提交、确认与接管。成员失联时不能只新建一个 worker 重做；接管前要知道旧授权何时失效，旧结果怎样隔离，已发生的业务作用能否查询。任务及回执的状态变化需要有明确的本地原子边界，而业务工具仍需自己的幂等记录。

本地 PRJ-2 使用一个 SQLite 权威任务板和独立业务服务，研究、执行、核验分别在子进程运行，驱动器按依赖顺序调度。它是持久队列的教学实现，没有使用分布式消息代理，也没有并行吞吐结论。每次租约 6 个虚拟刻度，每项工作最多三次领取，根 RPC 请求预算 240，项目截止 10,000 刻度；这些均为本次教学配置。

```powershell
uv run --project examples/ch36 --python 3.12 --locked python examples/ch36/run_study.py project2 --output outputs/project2-first
```

8 个任务经过 24 个角色工作项。首项执行者在服务已提交、尚未回传结果时以约定退出码 42 结束；租约到期后，新进程查询并恢复同一操作，恢复退出码为 0。最终服务中只有 3 张符合允许条件的工单，其余任务保留拒绝原因。工程入口、任务身份与独立读取逻辑见 `examples/ch36/src/book_reference/project2.py`。

### D.2.3 多租户：身份、数据与配额都要分别验收

多租户档位需要把可信身份、对象范围、数据隔离、配额、审计及管理权限连起来。每次创建、查询和恢复都要重新检查调用者能否访问目标对象，不能只在最初创建时验证 tenant。备份、日志与管理员路径也可能越过隔离边界，必须纳入实际部署验证。

当前本地探针只检查模拟服务的有限性质：`course-A`、`course-B` 使用相同操作标识可分别保存对象；属于 A 的测试 grant 不能用于 B 的新建动作。身份由受信本地驱动提供，grant 是内存对象，并非认证令牌。该证据不能证明真实 IAM、数据库行级安全、跨机器隔离、租户配额或真实密钥撤销已实现。

## D.3 上线与灰度验收

### D.3.1 上线前接受的是一组相互匹配的资产

上线检查包括代码、依赖、任务、政策、提示、模式与配置是否指向同一基线，以及拒绝、超时、恢复和取消是否仍能解释。密钥不得写入清单或实验原始记录；生产凭证应由真实受控设施提供。基础教学路径不读取任何真实凭证。环境构建与运行分开记录，首次获取 Python 或依赖可能联网，示例执行不需要网络。

部署验收还应检查实际业务作用。程序返回 0 只是必要信息；这里另从服务数据库读取字段、批准摘要及 `created` 事件，并与预先冻结的独立答案比较。正确拒绝的任务应没有新工单。任务级“已完成”和整个上线检查“通过”使用不同字段，不将两者混为同一个状态。

### D.3.2 灰度必须有范围和停止条件

灰度记录写清候选版本、允许对象、观察窗口、停止条件及恢复目标。本地样例把候选 `local-v2` 路由限定在 `T-DEMO-01`，故意将其政策声明改为不存在于当前基线的 `P20-A@9.9`。配置接收检查发现错配，在新业务分派前阻断，不向剩余七个任务扩展。这里的灰度范围是本地路由分配，没有真实线上流量。

停止条件不是看到任意错误才临时决定。本次预先规定：源摘要不符、政策不符、角色工作未收口、唯一作用不符，任一出现即停止。生产系统的错误率、延迟阈值和观察时间应由团队按业务风险定义；本地夹具没有提供这些性能或容量阈值。

## D.4 回滚、恢复与补偿

回滚先说明要回到哪个资产组合，再处理已经产生的业务作用。切回旧代码或配置，不会自动删除此前创建的工单，也不会撤回发出的通知。状态模式、任务输入和政策版本若已经不兼容，简单切换指针可能无法恢复服务。应在变更前确定兼容条件、备份与人工处理路径。

本次回滚演练将本地候选路由 `local-v2-canary` 清除，保留 `local-v1` 为当前版本，重新检查原配置与源码摘要，并比较回滚前后的业务快照。3 张既有工单及 3 个创建事件保持不变。样例没有修改数据库模式，也不执行工单删除，因此只能证明配置路由恢复和作用保持。

这与 Ch36 的任务恢复是两个检查：任务恢复处理“先前请求是否已经生效”；发布回滚处理“后续工作交给哪个版本”。两者都可能需要稳定业务标识，但不能用任务重启成功替代发布演练。本地回滚也没有证明降级到任意旧版本均安全，生产兼容性必须按实际变更核查。

## D.5 退役与责任交接

退役包括停止接收新任务、处理在途工作、撤销适用权限、归档必要数据并交接责任。任务排空要检查实际状态和未决作用，不能只确认 worker 进程已经退出。对结果未知的外部请求，即使不再继续自动执行，也仍须记录查询和人工处理责任。

本地样例先核对 24 个角色工作均已关闭，未决角色工作为 0，再把本地入口和测试 grant 开关置为禁用。随后实际调用接收检查，得到 `release_retired` 拒绝；最后使用 SQLite 备份接口保存控制记录。这个动作关闭的是本地驱动的接收通道，并未撤销任何真实组织账户或云端密钥。

原创教学记录保留在本机输出目录，用于复查；脚本没有自动删除数据。真实数据的保留、删除、法律或合同义务由 B 的治理材料确认，不能从本例复制出统一保留天数。备份本身也应说明访问范围与恢复验证，不能因为已经复制一个文件就宣布归档完成。

## D.6 复现、证据与扩展使用

完整复现包含本地项目、三个章节实验和上述生命周期演练：

```powershell
uv run --project examples/ch36 --python 3.12 --locked python examples/ch36/run_study.py all --output outputs/student-e-first
uv run --python 3.12 pytest
```

只运行本附录时，将 `all` 改为 `deploy` 并使用另一个新目录。`all` 输出的根 `report.json` 登记环境、数据清单和源摘要，各子报告分别列实际结果。`deploy/report.json` 汇总四项生命周期操作，`launch-project/` 保留角色事件、任务状态和业务数据库，`release.sqlite` 保存路由与接收状态，`tenant-probe.sqlite` 保存有限租户检查。仓库内 `examples/ch36/reports/study_20261120/` 提供可共享 JSON/JSONL 记录；SQLite 原始状态通过同版命令重建，不要求下载用户本机目录。

基础路径运行期无网络、无密钥。数据和规则均为本书原创虚构材料，执行时间、虚拟时间和生产恢复时间须区分。读者不应把每次相同确定性运行都当作新的独立样本；若接入真实模型、网络服务或外部队列，应新建实验卡，记录端点、版本、预算、重复、波动和权限范围。
