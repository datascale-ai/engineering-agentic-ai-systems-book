# Ch39 预发布事故响应与五要素回滚手册 (`rollback_runbook.md`)

## 1. 触发回滚的客观条件

满足以下任一条件立即暂停候选流量并启动回滚，禁止仅靠“重启进程”宣称恢复：

1. **配置错配**：预发布加载的政策阈值、模型路由或 Schema 版本与发布清单摘要不一致。
2. **权限越界或缓存残留**：高风险任务在缺少审批时被放行，或权限缓存命中了已撤销/旧版本的许可条目。
3. **业务验收失败**：独立读取 `service.sqlite` 发现重复工单、字段不符或轨迹与存储计数不一致。
4. **秘密泄露**：日志或 OpenTelemetry 导出链路出现未脱敏凭据特征（`sk-`、`Bearer ` 等）。

## 2. 标准五要素回滚序列（严格按序执行）

回滚不仅切换代码指针，必须按以下顺序联动恢复 **代码、配置、数据/状态、权限与缓存**：

| 序号 | 回滚对象 | 操作动作 | 验证判据 | 禁止误区 |
| --- | --- | --- | --- | --- |
| 1 | 入口流量 (`intake`) | 暂停新任务接入，等待在途幂等写操作到达安全检查点 | `in_flight_writes == 0` | 强杀写入中事务且不查外部状态 |
| 2 | 代码与依赖 (`code`) | 切换运行指针至上一已验收不可变版本（如 `release-v1.0.0`） | `active_release_id == target` | 仅在原地 `git pull` 未核验锁文件 |
| 3 | 配置与政策 (`config`) | 恢复上一版本政策、提示、模型路由与预算清单并校验 SHA-256 | `config_digest == target_digest` | 只回滚代码而保留新政策阈值 |
| 4 | 权限与缓存 (`permissions + cache`) | 撤销候选版本临时授权，强制清空/递增权限缓存代次（epoch bump） | `cache_version == target && stale_entries == 0` | 忽略权限缓存导致旧越权规则继续生效 |
| 5 | 数据核对与补偿 (`data`) | 独立读取业务库核对回滚前后合法工单完好无损；若候选已造成错误写入，登记显式补偿单 | `legitimate_tickets_preserved && drift_tickets == 0` | 直接清空数据库掩盖错误写入 |

## 3. 恢复验收标准

只有同时满足以下四项，才可将事故标记为“已恢复”：
1. 健康检查接口返回 `healthy` 且版本清单指向回滚目标；
2. 探针测试验证高风险无审批任务被正确拒绝（证明权限缓存已彻底清理）；
3. 探针测试验证标准合规任务成功创建唯一工单并通过 TA-01—TA-05 轨迹断言；
4. 审计日志记录完整时间线：故障注入时刻 -> 告警触发时刻 -> 回滚执行时刻 -> 业务验收通过时刻。
