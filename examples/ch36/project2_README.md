# PRJ-2：本地研究、执行与核验协作系统

版本 `PRJ-2-local-1`，2026-11-20。主责学生 E；统一案例为原创政策研究与模拟工单。运行只用 Python 标准库、SQLite，不调用真实模型或真实业务服务。原创代码和夹具采用根目录 MIT 许可。

## 学习目标和边界

在 Ch36 原有同一任务、政策和工具服务上增加三个可执行角色，观察消息、租约、角色交接、根预算和独立业务核验。它交付完整的本地最小路径，不只是给单进程函数增加角色名称；仍不包含正式知识检索、分布式消息代理、真实身份认证或生产流量。

首项任务逐字段复用 `T-DEMO-01`，其余七项检查金额与政策边界。当前只有两条原创政策；D/A 的正式 50 政策/60 任务基线与 C/F 的公共接口尚未收到冻结版本，本地模式不得冒称团队已确认。

从仓库根目录执行，输出目录必须尚不存在；不需要模型账号或密钥：

```powershell
uv sync --project examples/ch36 --python 3.12 --locked
uv run --project examples/ch36 --python 3.12 --locked python examples/ch36/run_study.py project2 --output outputs/project2-first
uv run --python 3.12 pytest examples/ch37/tests/test_student_e_studies.py
```

最后输出 `{"passed": true, "command": "project2"}`，整体退出码0。若输出目录存在，退出2并保留原目录。其他入口说明见 [STUDIES.md](STUDIES.md)。首次安装 Python/依赖可能联网，运行期无网络。

## 执行和故障路径

研究进程领取工作、读取任务及政策，提交判断、条款引用与两份内容摘要。驱动器在当前候选上关闭研究工作，随后执行进程读取已关闭研究；摘要不匹配即拒绝。执行者调用原 Engine，只有符合政策且具备受信测试 grant 才能新建模拟工单。核验进程使用只读连接检查实际状态，不能审批或创建工单；最终负责者仍是 coordinator。

驱动按依赖顺序启动进程，并非并行 worker 池。首项执行者在业务服务提交后抛出已命名的故障，子进程以42退出，尚未提交阶段候选。驱动推进受控时钟至旧租约之后，再起执行进程；新代次隔离旧领取者，Engine 从持久会话查询原操作标识，得到已有工单，再提交执行结果。42是内部预期故障，不是容忍任意命令失败的通用约定。

数据、任务板与工具服务处于不同事务边界。该实例验证一个已声明的中断窗口，没有声称驱动器任意位置退出后都能自动续跑。需要恢复整个控制进程时，应扩展可恢复调度日志、待发通知和 deadline 策略，再增加中断测试，不能复制输出目录后擅自重置根预算。

## 常见错误与定位

| 信号 | 定位与处理 |
| --- | --- |
| `asset_drift` | 对照 inventory 检查源码/输入差异；先审查、测试再显式seal，不能直接绕过 |
| `worker_role` / `worker_not_granted` | 检查阶段、可信进程身份、租约及任务终态 |
| `research_binding` | 研究后任务或政策已变；应按变更协议重做，不修改历史候选 |
| `verification_failed` | 独立读取实际工单和created事件，核对是否重复或字段/批准范围不符 |
| 根预算用尽、截止到达 | 停止自动接收，保留最后状态及负责人；不要清零计数继续执行 |

## 基础与进阶作业

基础：从新目录运行项目，说明8项任务的状态，定位首项42→0的进程记录，使用独立SQL查询证明首项只有一个工单和一个创建事件。提交角色/权限表、事件次序与根预算解释。

进阶：在保持同一 Engine 的条件下，引入整个调度器中断或真实队列适配；明确新增原子边界，测试接受候选后通知丢失、旧代次回传和核验截止。不得为制造差异移除业务授权。真实模型可另建适配器，分开保存模型与确定性结果。

评分：角色及接口20分、独立业务断言30分、恢复与故障证据25分、预算与限制15分、新目录复现10分。没有原始状态支持的“成功”不计业务断言分。
