## 稳定命令

从仓库根目录执行：

```powershell
uv sync --project examples/ch36 --python 3.12 --locked
uv run --project examples/ch36 --python 3.12 --locked python examples/ch36/run_study.py all --output outputs/student-e-first
uv run --python 3.12 pytest
uv run mkdocs build --clean --strict
```

将 `all` 改为 `project2` 只跑项目；改为 `experiments` 只跑 Ch19—21；改为 `deploy` 只跑附录D演练。每次选择新输出目录。成功退出0，独立接受条件失败退出1，配置/环境/目录拒绝退出2。内部子进程42仅用于已命名的提交后中断；外层检查它之后仍须有恢复0。

`all` 根报告列清单、源摘要、环境和每个子报告位置。基础运行无网络、无真实模型、无真实凭证。完整报告、事件、消息和逐试次结果由命令产生，已共享JSON/JSONL副本在 `reports/study_20261120/`。二进制SQLite不入库，可由同版命令重建。

## 指标与统计边界

Ch19 的业务分母固定20，18完成与1取消、1升级分列。协议使用权威RPC预算，通信开销另列发送尝试和回执尝试，丢失也保留；不把串行虚拟刻度写成系统性能。简化方案按自己的确认/重传策略发送，不被强迫执行协议组才有的查询。该对照同时改变多项机制，不能归因于单一租约或去重功能。

Ch20 的正确标签由独立人工答案评分，证据还需匹配适用版本和任务摘要；未知日期须保留两个可能版本。三成员初始共识、共识但答错、最终裁决、覆盖、分歧审查分别记录。五种子重复的是20道相近规则题，不能当100道独立题计算总体置信区间。审查模式直接执行规则检查，100/100若出现是构造算法的性质，不能支持真实模型辩论优势。字节不等于token；token和价格字段为null。

Ch21 评分分别读取实际后置状态和动作前置快照。未确认的提交既保留物理后置状态，也保留策略的unknown；业务成功要求有据确认。授权失效、无通路或旧episode未决的保护停止另计，不并入成功。两组始终保留相同接收端保护，因而请求被阻止而没有错误作用是应记录的有效结果。虚拟时间和API次数不是实测设备性能。

恢复时间从已触发故障到可核验继续步骤计算；未恢复保留null及终态，不只平均成功试次。B06/B07按观测次数注入，O没有发出第二次任务观测时不会遇到该扰动，报告保留此事实。固定种子中只有表单布局有变化，其余重复用于一致性检查。纯函数、有限脚本和模拟接收端通过，均不等于真实浏览器/模型/设备已验证。

## 失败定位与重建

先看根报告失败的是哪个子项，再查该子报告的任务/试次、事件、原始请求和接收理由。不要只重跑失败汇总；保留旧输出，新建目录验证修复。修改代码或输入后先审查，再测试并显式更新inventory；未经审查更新摘要会掩盖漂移。

项目的 `session.sqlite` 与 `service.sqlite` 有独立提交边界，协调队列也不跨库提交。配置演练没有数据库模式降级。新目录作者自检、同机干净副本与其他学生独立复现三者分别标注；本轮不替代团队接口确认或F签认。
